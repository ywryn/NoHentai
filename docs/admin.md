# 服务器 Admin（schema v2）

入口 `/#/admin`。所有编辑直接写入 Python / SQLite，无需 Git 提交、构建或部署。

## 内容与生效方式

| 数据 | 表 | 生效 |
| --- | --- | --- |
| 抓取来源 | galleries（原始 JSON 与查询列） | 完整同步成功后事务发布 |
| 人工覆盖 | gallery_overrides（每个 gid 独立版本） | 保存后立即生效；同步不覆盖人工值 |
| 实体书单 | books（独立 UUID、position、关联 gid、版本） | 按条保存、删除和排序立即生效；书目编号允许重复 |
| 每日规则 | daily_rules（独立 UUID 与版本） | 保存更新规则；同步成功才更新公开结果 |
| 翻译与 OCR 选择 | resources.translate | 后续请求读取；已打开工作台重新进入读取默认 OCR |
| 普通业务参数 / 密钥 | service_settings / credentials | 后续请求、新任务读取；密钥 Fernet 加密 |
| 内容历史 / 配置审计 | record_history / history | 按条字段差异、时间、操作；密钥仅记录字段名称 |
| 任务 / 步骤 / 调度 | jobs / job_steps / schedules | 队列持久化，后台 worker 执行 |
| 管理员 / 会话 | accounts / sessions | 密码 scrypt，Cookie 会话可撤销 |
| 封面 | media + uploads/*.webp | 上传后保存对应书目时应用 |

首页、详情、书单、每日列表和标签浏览分别使用专用 API；首页和标签在服务器分页，不下载完整收藏或标签翻译库。兼容 `/data/*.json` 仍从数据库生成，仅供旧页面和维护使用。SQLite 版本在保存事务中更新，各 API 进程据此失效缓存。首页在重新聚焦时检查版本并刷新；其他设备已有页面也可手动刷新查看新内容。

## 登录、账户和会话

首次升级 / 安装从独立的 `ADMIN_PASSWORD` 创建账户，之后数据库密码为准，修改环境变量不再改密。管理密码至少 16 字符且不能与翻译工作台密码相同。可在“账户与会话”修改密码、撤销某设备或退出全部设备；修改密码撤销全部会话并要求重新登录。

浏览器仅持有 HttpOnly、SameSite=Strict Cookie，HTTPS 下为 Secure；不再将管理 Token 写入 localStorage 或 sessionStorage。所有 Cookie 管理 POST 校验 CSRF，限制允许的 Origin。记住登录为 30 天，不记住为 12 小时且关闭浏览器后丢弃 Cookie。升级前的浏览器存储登录信息会清理，需要重新登录。旧 Token API 只为维护客户端兼容保留，不用于新后台。

登录限流、翻译限流和付费计数保存在 SQLite。不要直接开放 8000 端口，保持 Nginx 同域代理和 HTTPS。

## 按条编辑、冲突与恢复

列表服务器分页，可通过标题、gid、画廊链接及标签语法查找。每条记录独立版本，两人编辑不同条目互不阻塞；同条旧版本返回 409，草稿保留，可导出、重新加载并合并。离开未保存条目会确认，支持 Ctrl/Cmd+S。重新聚焦时更新无草稿记录；有草稿发生外部修改时提示冲突。

画廊显示来源值和人工值，可逐字段恢复来源，或恢复全部来源。允许 title、title_jpn、tags、category、uploader、hidden；隐藏控制公开展示，不构成私有权限。

“修改历史”展示编辑前基线与每次修改的差异，恢复会生成新版本，不抹掉历史。删除书目 / 规则可在“修改记录”恢复，恢复删除项保留内部 UUID 并追加到末尾。排序操作有审计，历史内容恢复不撤销位置，使用上移 / 下移调整。旧版整资源历史保留在数据库归档中，升级后的逐条历史从首次编辑建立基线。

每日规则保存和执行分开，可只同步当前分组；未改分组结果保留。任务排队后冻结规则，抓取期间规则版本变化则拒绝发布旧结果。

## 服务配置

按“收藏来源 / 翻译服务 / 文字识别”分组，普通地址、模型、超时、并发及额度有明确输入；密钥输入留空表示保留，支持明确清空或恢复环境变量继承。每项显示数据库 / 环境变量 / 默认值来源；不返回任何旧密钥明文。保存有独立组版本，冲突时保留草稿。

参数保存立即用于后续请求，排队任务仍使用冻结配置。每组可测试已保存配置；改动后旧测试结果标为过期。翻译 / OCR 测试会访问真实服务并可能计费，界面执行前确认；保存成功不代表连接可用。业务配置优先于服务器环境；账号、主密钥、路径只允许本机维护。

`CREDENTIAL_ENCRYPTION_KEY` 必须单独备份。数据库备份包含加密凭证及任务凭证快照；丢失主密钥无法解密。不要直接更换密钥；轮换必须解密并重新加密 credentials 和 jobs.config_ciphertext。

## 任务与调度

见 [每日同步](data-sync.md)。任务页提供阶段状态、安全数字进度、取消排队 / 运行任务、按当前配置重跑或原配置续跑。后者复用仍保留的成功步骤；已发布更近收藏来源时拒绝使用旧收藏检查点覆盖。

概览显示数据数量、各类最近成功、服务测试、worker 心跳、下次调度、备份和识别用量。“服务状态”保留细分探测；第三方探测仅由操作人触发。

## 备份与密码恢复

后台可创建和下载 SQLite 备份及配套 media.zip（有上传文件时生成）。下载必须登录；备份不在公开目录。保留最近七份，本机恢复流程见 [部署文档](vultr-deployment.md)。在线不提供一键整库覆盖。

忘记密码时，把新密码写入本机权限 0600 的文件，以生产环境和数据路径执行 `python -m backend.cli reset-admin --password-file /path/to/password`，随后安全删除临时文件。此操作撤销全部会话。数据库和主密钥分别保管。
