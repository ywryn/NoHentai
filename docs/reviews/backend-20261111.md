## 有依据的改动

| 模块 | 问题 | 改动 |
| --- | --- | --- |
| `catalog.py` | 详情读取全部画廊覆盖记录；每次请求读取约 3.1 MB 翻译词典 | 按 `gid` 读取覆盖记录；以同一事务内的目录修订号复用已解析词典，修订后自动失效 |
| `records.py` | 管理画廊每页逐条读取源数据及覆盖，默认页重复扫描整个有效目录；书目关联也逐条查找 | 默认列表直接使用位置索引；搜索列表只物化一次结果；源数据和关联画廊批量读取 |
| `jobs.py` | 最近 50 个任务的步骤逐任务查询 | 一次读取任务，再一次批量读取步骤 |
| `db.py` | 每次限流请求先清理过期计数，增加写锁竞争 | 单条原子 UPSERT 完成限额与到期重置；约每 128 次做一次索引化清理；为过期维护增加兼容性索引 |
| `upstream.py` | JSON 上游响应无大小限制 | 流式读取并限制为 16 MiB；验收模式在传输前拒绝外网调用 |
| `main.py`、`observability.py` | API 错误难以关联，异常日志若直接输出可能泄露凭据 | 响应增加 `X-Request-ID`；服务端记录请求 ID、操作、异常类型与代码位置，不记录请求体、URL 或异常原文 |

现有 API 请求和响应结构保持不变，额外增加 `X-Request-ID` 响应头。索引为 `CREATE INDEX IF NOT EXISTS`，不改变表、字段或 `user_version`，旧代码仍可读取数据库。

## 验证与性能

在生产数据库的一致性副本中保留 4,246 个画廊，并仅在测试副本加入约 4,000 条空覆盖记录，以复现覆盖记录增长。进程预热后分别运行相同 Python 操作，以下为单次实验的中位数，单位 ms；测试受主机负载影响，并非线上延迟承诺。

| 操作 | 原部署代码 | 优化后 |
| --- | ---: | ---: |
| 画廊详情，40 次 | 34.48 | 1.05 |
| 管理画廊默认列表，30 次 | 251.79 | 2.84 |
| 管理画廊搜索，10 次 | 387.66 | 161.64 |

20 线程并发申请 200 个不同限流键，原代码三轮为 367–460 ms，优化后为 249–268 ms，且每轮均放行 200 次。单线程限流收益较小，主要收益是降低高并发写锁占用。

- Python 集成/接口测试：99 项通过。新增词典失效、并发限流、敏感日志、验收环境禁外网与上游 JSON 大小限制测试。
- JavaScript 契约测试：18 项通过。
- 8444 实际验收：健康检查、目录、统计及手机端前台、后台登录页通过；浏览器无 JavaScript 错误，外网相关 API 返回受控 503，生产 API、worker 和 8443 前端验收站仍正常运行。

## 已知限制

- 复杂目录搜索仍需按现有 JSON 数据扫描有效画廊；在约 4,000 条覆盖记录的压力副本中，中位数约 162 ms。本次未引入冗余搜索索引或全文搜索迁移，以避免同步和覆盖写入的额外一致性风险。
- OCR、翻译和上游同步的真实外部调用在验收服务中刻意禁用；它们的逻辑由隔离的模拟服务测试覆盖。正式合并前应在受控环境执行一次外部连接验证。
- 上游 URL 允许列表与 DNS 地址检查已有实现；DNS 检查与 HTTP 连接之间仍存在重新解析窗口。当前验收环境以网络层禁止外网作为额外约束，生产合并前应结合 egress 策略评估进一步收紧。
